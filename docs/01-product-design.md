# 渡口 Harbor · 功能设计

> 工作名：**渡口 Harbor**（暂定）  
> 一句话：在两台电脑之间架一座桥，把文件夹点对点同步过去，不经过任何云端。  
> 形态：Windows / macOS / Linux 桌面应用，局域网优先，源端与目的端两种角色。

---

## 1. 产品定位

### 1.1 要解决的问题

| 场景 | 现有做法 | 痛点 |
| --- | --- | --- |
| 换电脑，迁移几十 GB 工作目录 | 移动硬盘、网盘 | 慢、要反复拷贝、目录结构丢失 |
| 设计/视频素材从工作站分发到同事电脑 | 共享盘、IM 传文件 | 大文件传不动、中断要重来、无校验 |
| 内网/离线环境批量交付资料 | FTP、临时 HTTP 服务 | 配置复杂、无断点续传、无权限控制 |
| 长期把某几个文件夹备份到另一台机器 | rsync / 同步盘 | 命令行为主、跨平台体验差、走公网 |

**渡口**做的事：让 A 电脑把指定文件夹"发布"出来，B 电脑像浏览本地目录一样挑选、同步到本地任意位置。全程 P2P，局域网满速，断线可续，并且对"谁能看、能看什么、看完是否留痕"有明确控制。

### 1.2 设计原则

1. **点对点，无云**：文件字节不经过第三方服务器；默认只在局域网内可达。
2. **源端最小暴露**：源端只读、按文件夹授权、按连接审批；不提供任意路径读取能力。
3. **中断不是失败**：任何时刻拔网线、关应用、重启电脑，恢复后从分块继续，不重传已完成部分。
4. **默认安全**：加密传输、首次配对核对校验码、失败锁定、全量审计，不需要用户额外配置。
5. **结果可验证**：每个文件传输完成后做内容哈希校验，UI 明确展示"已校验"，而不是"进度 100%"就算完成。
6. **原生感**：跟随系统窗口、托盘、通知、快捷键；文件选择用系统对话框。

### 1.3 非目标（v1 不做）

- 不做云盘/跨公网中继（v2 再评估，需额外威胁建模）。
- 不做双向实时同步（v1 单向：源端 → 目的端）。
- 不做手机端（协议层预留，v2 提供 iOS/Android 接收端）。
- 不做文件在线预览/编辑，只做传输与落盘。
- 不做多源端聚合（一个目的端同一时间连接一个源端，但可有多个同步任务）。

## 2. 角色与模式

### 2.1 两种角色

| 能力 | 源端（Source） | 目的端（Destination） |
| --- | --- | --- |
| 选择文件夹 | 选择本机要共享的目录 | 选择源端要同步的目录 + 本机保存位置 |
| 启动服务 | 监听端口、广播 mDNS、生成连接码 | — |
| 展示信息 | 连接码、IP、端口、主机名、指纹、共享清单 | 连接状态、源端信息、任务进度 |
| 连接发起 | 被动接受 | 主动发现/输入连接码 |
| 数据流向 | 读本机 → 发送 | 接收 → 写本机 |
| 权限 | 授予只读访问，可随时撤销 | 只能读取被授权的目录 |
| 审批 | 新设备接入需本机确认（可配置） | 需输入连接码或经源端审批 |

### 2.2 模式规则

- 首次启动选择角色；主界面左上角可随时切换，切换时若服务运行中需二次确认（会断开现有连接）。
- **同一进程同一时刻只运行一种角色**（v1）。理由：降低权限与端口暴露面，UI 也不用同时呈现两套信息。
- 数据（共享配置、信任设备、任务历史）共用同一 SQLite，切换角色不丢配置。
- v2 可选"双角色"：后台常驻接收端 + 前台共享端，需单独设计端口与权限隔离。

## 5. 核心流程

### 5.1 源端：从启动到可被连接

| 步骤 | 用户动作 | 系统行为 | 界面反馈 |
| --- | --- | --- | --- |
| 1 | 首次启动选择"源端" | 创建默认配置；检查防火墙/权限 | 引导页 → 源端首页（服务未开启） |
| 2 | 点击"添加文件夹" | 打开系统目录选择器；扫描文件数与体积 | 弹窗内实时显示"已扫描 2,341 个文件 · 18.6 GB" |
| 3 | 配置名称、过滤规则、权限 | 写入 SQLite；启动扫描任务（后台） | 文件夹出现在列表，状态"准备中 → 共享中" |
| 4 | 点击"开启共享服务" | 绑定端口、生成自签证书、启动 mDNS、生成连接码 | 顶部状态"运行中"；展示连接码/二维码/IP/指纹 |
| 5 | 点击"复制连接信息" | 生成文本摘要写入剪贴板 | Toast"连接信息已复制" |
| 6 | 收到连接请求 | 校验连接码 → 弹出审批（SAS） | 审批弹窗 + 系统通知 + 托盘角标 |
| 7 | 点击"允许连接"并核对校验码 | 设备写入信任库，建立会话 | 首页出现"已连接设备"，开始接收清单请求 |
| 8 | 需要停止 | 点击"停止服务" | 二次确认：有 1 个传输中的任务，停止将保留断点；确认后断开 |

### 5.2 目的端：发现 → 配对 → 选择 → 同步

| 步骤 | 用户动作 | 系统行为 | 界面反馈 |
| --- | --- | --- | --- |
| 1 | 进入"连接源端" | 启动 mDNS 浏览；读取历史连接 | 列表展示局域网设备；无设备时给出排查提示 |
| 2 | 点击设备"配对" | 建立 TLS 连接，读取源端信息 | 弹出连接面板，显示源端名称/系统/指纹 |
| 3 | 输入 6 位连接码（或等待源端审批） | SPAKE2 校验；输错计数 | 输入框逐位；错误提示"连接码不正确，还可尝试 4 次" |
| 4 | 两端核对 SAS | 派生 6 位校验码，比对 | 双端同一校验码；勾选"记住此设备" |
| 5 | 浏览远端文件夹 | 请求共享清单（只返回授权范围） | 文件夹列表 + 子目录树 + 文件数/大小 |
| 6 | 勾选文件夹 | 估算传输量与本地可用空间 | 底部汇总"已选 2 个 · 24.3 GB"；空间不足时标红 |
| 7 | 选择保存位置 | 系统目录选择器；校验可写性 | 路径展示，支持"在访达中显示" |
| 8 | 选择同步方式/冲突策略 | 保存任务草稿 | 说明文案随选项变化（镜像会删除本地多余文件） |
| 9 | 点击"开始同步" | 创建任务、拉取清单、开始传输 | 跳转任务页；顶部总进度、速度、ETA |
| 10 | 中途断网 | 自动重连（指数退避），恢复会话 | 状态"连接中断，正在重连（第 2 次）"，进度不回退 |
| 11 | 关闭应用再打开 | 加载未完成任务，校验临时文件 | 任务卡"已恢复 · 从断点继续"，已传分块不重传 |
| 12 | 完成 | 文件级校验、写数据库、通知 | "同步完成 · 2,341 个文件已校验"；可打开目录 |

### 5.3 断线恢复（用户可见状态机）

```
准备中 → 扫描中 → 同步中 ⇄ 暂停中
                   ↓
              连接中断（自动重连，最多 5 次，退避 2/4/8/16/30s）
                   ↓ 成功
              恢复中（校验临时文件 + 对齐分块）→ 同步中
                   ↓ 失败
              已中断（保留断点，可手动继续 / 换网络后重试）
```

- UI 必须显示"已恢复 N 次"与"已跳过 X GB 已传数据"，让用户确信没有重传。
- 应用重启后未完成任务自动进入"待恢复"，不自动开始（避免占用带宽），一键继续。

### 5.4 连接审批（安全关键路径）

1. 目的端发起 → TLS 握手完成 → 读取源端证书指纹。
2. 目的端提交连接码证明（SPAKE2），源端校验通过。
3. 源端生成 SAS（6 位），目的端本地同样计算并显示；**源端弹窗要求用户肉眼比对**。
4. 用户勾选"记住此设备"→ 双方保存设备公钥，后续连接走签名挑战，不再需要连接码。
5. 拒绝/超时（60s）→ 关闭连接，记录审计；同一 IP 连续 5 次失败锁定 10 分钟。

## 6. 同步语义（必须无歧义）

### 6.1 三种同步方式

| 方式 | 新增文件 | 源端修改 | 源端删除 | 本地多余文件 | 适用 |
| --- | --- | --- | --- | --- | --- |
| **增量同步**（默认） | 传输 | 覆盖（按冲突策略） | 不处理 | 保留 | 日常备份、资料分发 |
| **镜像同步** | 传输 | 覆盖 | 删除（移入隔离区） | 删除（移入隔离区） | 保持两台机器一致 |
| **仅新增** | 传输 | 跳过 | 不处理 | 保留 | 只补充缺失文件，绝不动本地 |

补充规则：

- 删除只作用于**任务根目录内**、且**由本任务管理**的文件；不触碰任务目录之外。
- 隔离区：`<任务根>/.harbor-trash/<时间戳>/...`，默认保留 7 天，可在设置中清空；UI 明示"可从隔离区恢复"。
- 任务根目录若包含用户已有文件，首次创建任务时提示"该目录已有 N 个文件，镜像模式会将其移入隔离区"。

### 6.2 文件判定顺序

对每个相对路径：

1. 应用过滤规则（排除目录/文件、隐藏文件、大小上限、特殊文件）。
2. 本地不存在 → 传输。
3. 本地存在且大小 + mtime 相同 → 跳过（可选"深度校验"逐块比对哈希）。
4. 本地存在且内容哈希相同 → 跳过并更新元数据。
5. 本地存在但内容不同 → 按冲突策略处理（覆盖 / 跳过并标记冲突 / 保留两者 → `文件名 (本地 2024-05-01).ext`）。
6. 源端已删除 → 按同步方式处理（镜像删除；其余忽略）。

### 6.3 文件名与路径

| 情况 | 处理 |
| --- | --- |
| Windows 非法字符 `\ / : * ? " < > \|` | 替换为 `_`，并记录映射到任务报告 |
| Windows 保留名 `CON PRN AUX NUL COM1..9 LPT1..9` | 前缀 `_` |
| 结尾空格/句点（Windows） | 去除后加 `_` |
| 路径超过 Windows 260 字符 | 启用 `\\?\` 长路径；仍超限则截断文件名并追加 8 位哈希 |
| macOS 文件名 NFD/NFC 差异 | 统一以 NFC 比较，落盘保持源端形式 |
| 大小写不敏感卷上的同名碰撞 | 后到者追加 ` (2)`，报告中列出 |
| 符号链接 | 默认跳过；可选仅复制指向共享根内的相对链接 |
| 空目录 | 创建 |
| 设备文件 / FIFO / Socket | 跳过并计数 |
| 隐藏文件 | 默认包含（排除 `.DS_Store`、`Thumbs.db`、`desktop.ini` 等系统垃圾） |

### 6.4 元数据

- 修改时间：默认保留（可在设置关闭）。
- 权限位：Linux/macOS 保留 `rwx`；Windows 仅保留只读属性。
- 扩展属性 / ACL / 资源分支：v1 不保留，报告中提示。
- 文件属主：不保留（跨机器无意义）。

### 6.5 过滤规则

- 内置默认排除：`.git/`、`node_modules/`、`.DS_Store`、`Thumbs.db`、`desktop.ini`、`$RECYCLE.BIN/`、`*.tmp`、`~$*`、`.harbor-trash/`。
- 支持 glob（`*`、`**`、`?`、`[abc]`）与目录后缀 `/`；大小写按源端平台语义。
- 规则编辑提供"测试"输入框，实时显示某路径是否会被排除。
- 单文件大小上限：不限 / 100 MB / 1 GB / 自定义。

## 7. 安全设计（概要）

完整实现见 [技术方案 §5](03-technical-design.md#5-安全实现)。

### 7.1 威胁模型

| 威胁 | 场景 | 对策 |
| --- | --- | --- |
| 窃听 | 同网段抓包 | TLS 1.3（AEAD），前向保密；不提供明文模式 |
| 中间人 | 伪造源端/目的端 | 自签证书指纹固定 + SPAKE2 连接码 + 双端 SAS 人工核对 |
| 未授权访问 | 猜到 IP/端口 | 默认需连接码或源端审批；仅信任设备可免审批（可关） |
| 暴力破解连接码 | 脚本撞 6 位码 | 6 位码 10 分钟有效、单次使用；每 IP 5 次失败锁定 10 分钟；全局速率限制 |
| 路径穿越 | 请求 `../../etc/passwd` | 协议不接受绝对路径；服务端 canonicalize 后校验前缀；拒绝 `..`/NUL/绝对路径 |
| 恶意文件名 | 目的端写入系统目录 | 按目标平台清洗文件名；落盘前再次校验父目录在任务根内 |
| 越权读取 | 访问未授权共享 | 按 share_id + 会话授权校验；共享关闭立即失效 |
| 重放/会话劫持 | 复用旧会话令牌 | 会话令牌绑定 TLS 通道与随机 nonce，24h 过期，重连需重新认证 |
| 本地残留 | 临时文件泄露 | 临时目录权限 0700；取消任务时可选择安全删除 |
| 审计缺失 | 无法追溯 | 全事件落库，含设备、IP、结果、耗时；可导出 |

### 7.2 权限模型

- 源端：文件夹级授权（v1 只支持顶层文件夹），操作仅 `read/list/stat`；协议层没有 `write/delete` 消息。
- 目的端：只能写入用户本次选择的根目录；不跟随符号链接（避免写到根外）。
- 信任设备：保存 `device_id + Ed25519 公钥 + 名称`；撤销立即断开现有会话。
- 默认配置：新设备必须审批；仅信任设备可重连；不允许匿名浏览（连接码也拿不到清单，必须先过审批）。

### 7.3 用户可见的安全提示

- 首次配对页固定展示："请确认两台电脑显示相同的 6 位校验码。若不一致，可能有人在中间转发，请拒绝连接。"
- 镜像模式删除前提示 + 隔离区说明。
- 连接码区域标注有效期与"仅可使用一次"。
- 设置中"仅允许已信任设备连接"默认开启，关闭时给黄色警示。

## 8. 断点续传（用户视角）

| 中断点 | 恢复粒度 | 用户看到 |
| --- | --- | --- |
| 单文件传输中网络断开 | 分块（平均 1 MiB） | "已恢复 · 从 68% 继续" |
| 应用崩溃/被关闭 | 分块；启动时校验临时文件 | "正在恢复上次任务（3/5）" |
| 电脑重启 | 同上，任务标记"待恢复" | 任务卡"上次中断于 10:42，点击继续" |
| 源端文件在传输中被修改 | 该文件重新传（不污染已传块） | 文件状态"源文件已变化，重新传输" |
| 目的端磁盘满 | 暂停任务，保留断点 | 横幅"磁盘空间不足，已暂停；释放 3.2 GB 后可继续" |
| 用户主动暂停 | 分块 | 状态"已暂停 · 已传 12.6 GB" |
| 切换网络（Wi-Fi → 有线） | 重连后分块 | "网络已切换，正在恢复" |

技术要点（见技术方案 §6）：内容分块 + 块级 BLAKE3 + 内容寻址块缓存 + SQLite WAL 断点日志 + 临时文件原地写 + 原子替换。
