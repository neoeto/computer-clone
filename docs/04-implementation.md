# M1 实现说明

> 对应里程碑：M1「骨架」。目标是把"两台电脑能互相发现、安全配对、浏览共享目录"跑通。
> M2 文件传输已完成，见 [M2 实现说明](06-m2-implementation.md)；M3 的 SPAKE2、设备密钥、
> 信任设备与审计见 [M3 实现说明](07-m3-security.md)。本文保留 M1 的实现与安全边界记录。

## 1. 已实现

### 源端

- 添加共享文件夹：调用系统目录选择器，校验目录、去重、拒绝嵌套共享目录。
- 共享开关 / 移除共享：写入配置并立即生效，目的端刷新清单后不可见。
- 启动 / 停止共享服务：绑定 `0.0.0.0:47821`（端口占用时自动改用随机端口）。
- 连接码：6 位、10 分钟有效、单次使用，认证成功后自动轮换；可手动刷新。
- 源端信息：本机 IPv4 地址、端口、证书 SHA-256 指纹、共享目录（文件数与体积）、二维码。
- 新设备审批：弹窗展示设备名、系统、地址、双端一致的 6 位 SAS；允许 / 拒绝，60 秒超时。
- 已连接设备与实时活动：连接、断开、审批、服务启停均记录在 UI 事件流中。
- 复制源端信息摘要到剪贴板。

### 目的端

- mDNS 自动发现（`_harbor._tcp.local.`），2 秒轮询刷新。
- 手动连接：6 位连接码 + IP + 端口；支持从发现列表一键填入地址与指纹。
- 配对等待：显示 SAS，源端确认后自动进入下一步；可取消（后端 CancellationToken）。
- 远端共享清单：名称、文件数、体积；源端暂停的目录自动隐藏。
- 只读浏览：目录进出、显示文件大小；路径穿越与符号链接由服务端拒绝。
- 选择要同步的文件夹、设置本地保存目录（M1 仅保存选择，不写文件）。
- 断开连接、异常提示。

### 通用

- 单角色模式，角色保存在本机；切换角色会停止服务或断开连接。
- TLS 1.3 传输；自签证书；连接时比对发现记录中的指纹前缀。
- 服务端路径安全：拒绝绝对路径、`..`、NUL；canonicalize 后必须在共享根内；符号链接目录拒绝。
- 失败锁定：6 位码错误 5 次后锁定，需轮换连接码或重启服务。
- 浏览器预览模式：无 Tauri 时自动使用演示数据，便于 UI 评审与截图；生产构建不启用。

## 3. 运行

### 环境

- Rust 1.85+（本机用 1.90）
- Node.js 20+、pnpm 10
- macOS：Xcode Command Line Tools；Linux：WebKitGTK 等 Tauri 依赖；Windows：WebView2
- Tauri CLI 由根目录的 `@tauri-apps/cli` 提供（`pnpm install` 时安装）

### 启动桌面应用

```bash
pnpm install
pnpm app:dev
```

Tauri 会执行 `pnpm --dir apps/desktop dev` 启动 Vite（1420），再打开原生窗口。

发布与签名见 [发布与签名](05-release-signing.md)。

> 数据目录默认是 `~/Library/Application Support/Harbor`（macOS）、`%APPDATA%\Harbor`（Windows）、
> `~/.local/share/Harbor`（Linux）。可用 `HARBOR_DATA_DIR=/path` 覆盖，便于便携运行或测试。

### 构建

```bash
pnpm --dir apps/desktop build
cargo build -p harbor-desktop
# 或完整安装包（Tauri CLI 已随 pnpm install 安装）
pnpm app:build
```

### 只预览 UI（不需要 Tauri）

```bash
pnpm --dir apps/desktop dev
# 打开 http://127.0.0.1:1420 —— 自动进入浏览器演示数据模式
```

### 测试

```bash
cargo test -p harbor-core
```

- 33 个单元测试：身份持久化、连接码校验/锁定、帧编解码、共享目录遍历与符号链接、
  FastCDC 分块、位图、路径清洗、任务状态迁移。
- 1 个端到端测试：两个 Engine 通过真实 TCP + TLS 完成 hello → 连接码 → SAS 审批 → 浏览；
  同时覆盖错误码、拒绝、停用共享、路径穿越与停止服务。
- 1 个 M2 传输端到端测试：增量 / 仅新增 / 镜像 / 保留两者、64 MiB 大文件暂停续传、
  无效数据票据与路径穿越。见 `tests/transfer_e2e.rs`。

## 5. 通信流程（M1）

```text
目的端                                    源端
  │ TCP :47821                             │
  ├──────────── TLS 1.3 ClientHello ──────>│
  │<─────────── 自签证书（记录指纹）────────┤
  ├──────────── hello {device} ───────────>│
  │<─────────── hello {device, fp, port} ──┤
  ├──────────── auth {code} ──────────────>│  校验 + 立即轮换
  │<─────────── auth_pending {req, sas} ───┤
  │                                        │  UI 弹窗，核对 SAS
  │                                        │  用户点击"允许连接"
  │<─────────── auth_ok {session} ─────────┤
  ├──────────── list_shares ──────────────>│
  │<─────────── shares[] ──────────────────┤
  ├──────────── browse {share, path} ─────>│  canonicalize + 前缀校验
  │<─────────── browse {entries[]} ────────┤
```

帧格式：`u32 BE 长度 + JSON`，单帧上限 2 MiB；控制通道复用同一条 TLS 连接。

## 6. M1 安全边界

**已做**

- TLS 1.3（rustls，ring），禁用 TLS 1.2 及以下。
- 自签证书 + SHA-256 指纹；发现记录带指纹前缀，连接时比对。
- 6 位连接码常量时间比较、10 分钟过期、单次使用、5 次失败锁定。
- 双端 SAS 人工核对；源端必须显式批准。
- 服务端只读授权；路径穿越、符号链接逃逸、NUL/绝对路径均拒绝。
- 两端的连接/审批事件只在本地内存中，不上传任何信息。

**M1 明确不做（不要误用为生产安全）**

- 连接码仍通过 TLS 传输，理论上可被能终止 TLS 的中间人转发；SPAKE2 在 M3 实现。
- 没有设备密钥/信任库，每次连接都需要连接码 + 审批。
- 没有持久化审计，应用重启后事件清空。
- 文件传输已在 M2 实现，但连接码仍走 TLS、没有设备密钥信任库；数据连接安全边界见
  [M2 实现说明 §10](06-m2-implementation.md#10-关键安全边界)。

## 7. 已知问题

1. 源端服务绑定 `0.0.0.0`，首次启动时 Windows / macOS 可能弹出防火墙或本地网络权限提示。
2. mDNS 在部分企业网络被禁用；此时使用手动 IP + 连接码。
3. 共享目录扫描是全量同步扫描，超大目录（>100 万文件）首次添加会阻塞数秒；M2 改为后台增量。
4. 配置使用 JSON，非原子多进程安全；M2 迁移 SQLite。
5. UI 的图标文案与组件在 M1 中只覆盖主要流程，托盘、通知、快捷键尚未接入。
6. 浏览器演示模式与原生命中系统是不同的运行路径；原生运行需在可写数据目录下启动。
